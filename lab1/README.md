# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа `Linear(4, 8) -> ReLU -> Linear(8, 3)` на датасеті Iris. Прямий прохід, стабільна крос-ентропія та зворотний прохід реалізовані вручну в NumPy (усі обчислення у `float64`). Коректність градієнтів перевірено двома незалежними методами: звіркою з PyTorch autograd і чисельним диференціюванням.

## 1. Дані та початкові параметри

Датасет Iris завантажується через `sklearn.datasets.load_iris()`. Поділ на навчальну й тестову вибірки стратифікований: класи опрацьовуються послідовно в порядку 0, 1, 2, індекси кожного класу перемішуються одним генератором `np.random.default_rng(0)`, перші 35 індексів відносяться до навчальної вибірки, решта 15 — до тестової. Загальний обсяг вибірок: 105 навчальних і 45 тестових обʼєктів.

Середнє значення та стандартне відхилення (`ddof=0`) обчислюються виключно на навчальній вибірці й застосовуються до обох вибірок. У межах поточних перевірок тестова вибірка не використовується.

Параметри мережі ініціалізує окремий генератор `np.random.default_rng(0)`, послідовність ініціалізації — спочатку `W1`, потім `W2`:

| Параметр | Форма | Ініціалізація |
|---|---|---|
| `W1` | (4, 8) | нормальний розподіл, $\mu = 0$, $\sigma = \sqrt{2/4}$ |
| `b1` | (8,) | нулі |
| `W2` | (8, 3) | нормальний розподіл, $\mu = 0$, $\sigma = \sqrt{2/(8+3)}$ |
| `b2` | (3,) | нулі |

Матриці ваг у NumPy мають форму (вхід, вихід), тому прямий прохід записується як `X @ W + b`.

## 2. Прямий прохід і функція втрат

Для пакета $X \in \mathbb{R}^{N \times 4}$, $N = 105$:

$$Z_1 = X W_1 + \mathbf{1} b_1^{\mathsf T}, \qquad A_1 = \max(0, Z_1), \qquad Z_2 = A_1 W_2 + \mathbf{1} b_2^{\mathsf T}.$$

Крос-ентропія обчислюється через log-softmax зі зсувом на максимум рядка. Для $m_i = \max_k z_{ik}$:

$$\log p_{ik} = z_{ik} - m_i - \log \sum_j e^{z_{ij} - m_i}, \qquad \mathcal{L} = -\frac{1}{N} \sum_{i=1}^{N} \log p_{i, y_i}.$$

Після зсуву всі показники недодатні, тому значення експоненти не перевищують одиниці й переповнення виключене. Серед доданків суми завжди присутній принаймні один, що дорівнює одиниці (той, для якого $z_{ij} = m_i$), тому логарифм береться від числа, не меншого за одиницю, і ділення $0/0$ також виключено. Softmax окремо не обчислюється: ймовірності $P = e^{\log P}$ відновлюються лише у зворотному проході, коли вони фактично потрібні.

## 3. Зворотний прохід

Для одного обʼєкта $\mathcal{L}_i = -z_{i, y_i} + \log \sum_j e^{z_{ij}}$, звідки

$$\frac{\partial \mathcal{L}_i}{\partial z_{ik}} = p_{ik} - [k = y_i].$$

Оскільки втрата усереднена за обʼєктами, похідна додатково ділиться на $N$:

$$\frac{\partial \mathcal{L}}{\partial Z_2} = \frac{1}{N}(P - Y), \qquad Y_{ik} = [k = y_i].$$

Далі застосовуються похідні двох афінних шарів і ReLU. Позначено $\delta_2 = \partial \mathcal{L}/\partial Z_2$, $\delta_1 = \partial \mathcal{L}/\partial Z_1$:

$$\nabla_{W_2} \mathcal{L} = A_1^{\mathsf T} \delta_2, \qquad \nabla_{b_2} \mathcal{L} = \sum_{i=1}^{N} (\delta_2)_{i \cdot},$$

$$\delta_1 = \left( \delta_2 W_2^{\mathsf T} \right) \odot \mathbb{1}[Z_1 > 0],$$

$$\nabla_{W_1} \mathcal{L} = X^{\mathsf T} \delta_1, \qquad \nabla_{b_1} \mathcal{L} = \sum_{i=1}^{N} (\delta_1)_{i \cdot}.$$

Сумування за рядками у градієнтах зсувів пояснюється тим, що зсув додається до кожного рядка пакета: у прямому проході це реалізується через broadcasting, а у зворотному цій операції відповідає підсумовування за віссю пакета.

У точці нуль ReLU не має похідної в класичному сенсі, її субградієнт належить проміжку $[0, 1]$. У реалізації використано маску `Z1 > 0`, тобто значення 0 у самій нулі — аналогічний вибір застосовує PyTorch, тому на результати звірки це не впливає.

### Розмірності масивів

| Масив | Форма |
|---|---|
| `X` | (105, 4) |
| `Z1`, `A1` | (105, 8) |
| `Z2`, `log P`, `P`, `Y` | (105, 3) |
| `dZ2` | (105, 3) |
| `dA1`, `dZ1` | (105, 8) |
| `dW1` | (4, 8) |
| `db1` | (8,) |
| `dW2` | (8, 3) |
| `db2` | (3,) |

Форма кожного градієнта збігається з формою відповідного параметра.

### Значення, що кешуються для зворотного проходу

| Значення | Де використовується |
|---|---|
| `X` | у $dW_1 = X^{\mathsf T} dZ_1$ |
| `Z1` | для формування маски ReLU $\mathbb{1}[Z_1 > 0]$ |
| `A1` | у $dW_2 = A_1^{\mathsf T} dZ_2$ |
| `log P` | для відновлення $P = e^{\log P}$ у $dZ_2$ |
| `y` | для побудови унітарного кодування $Y$ |
| `W2` | у $dA_1 = dZ_2 W_2^{\mathsf T}$; є параметром, окремого кешування не потребує |

Замість `Z1` допустимо зберігати безпосередньо маску або використовувати умову `A1 > 0` — для ReLU обидва варіанти еквівалентні. Значення `Z2` після обчислення `log P` більше не потрібне. Обсяг кешу активацій зростає лінійно з розміром пакета.

## 4. Звірка з PyTorch

Еталонна мережа зібрана як `nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 3))` у режимі `double`. Оскільки `torch.nn.Linear` зберігає ваги у формі (вихід, вхід), при копіюванні параметрів матриці транспонуються, а градієнти, отримані через autograd, транспонуються у зворотному напрямку для приведення до узгоджених форм. У `nn.functional.cross_entropy` подаються сирі логіти без попереднього застосування softmax, оскільки log-softmax вбудований у цю функцію.

Втрата PyTorch: 1.456200780114282

|---|---|---|
| Втрата | 2.220e-16 | так |
| Градієнт `W1` | 5.551e-17 | так |
| Градієнт `b1` | 3.816e-17 | так |
| Градієнт `W2` | 1.110e-16 | так |

Критерій $|a - b| \le 10^{-12}$ виконано з суттєвим запасом. Усі різниці лежать на рівні машинного епсилона `float64` і зумовлені відмінним порядком підсумовування в NumPy та PyTorch.

## 5. Чисельна перевірка окремих градієнтів

Застосовано метод центральної різниці з кроком $\varepsilon = 10^{-6}$ на початкових вагах і тих самих 105 обʼєктах:

$$g_{\text{num}} = \frac{\mathcal{L}(\theta_i + \varepsilon) - \mathcal{L}(\theta_i - \varepsilon)}{2\varepsilon}.$$

| Параметр | Градієнт `backward()` | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| `W1[0, 0]` | -0.019920184 | -0.019920184 | 6.034e-11 | так |
| `b1[0]` | -0.070566112 | -0.070566112 | 3.633e-11 | так |
| `W2[0, 0]` | 0.135230209 | 0.135230209 | 9.218e-11 | так |
| `b2[0]` | 0.085521645 | 0.085521645 | 1.460e-10 | так |

Критерій $|g_{\text{num}} - g_{\text{manual}}| \le 10^{-7}$ виконано. Спостережувані різниці порядку $10^{-10}$ є очікуваними: похибка центральної різниці складається з похибки зрізання $O(\varepsilon^2) \approx 10^{-12}$ та похибки округлення $O(u/\varepsilon)$, де $u \approx 2.2 \times 10^{-16}$, що становить величину порядку $10^{-10}$. У сумарній похибці переважає саме друга складова.

## 6. Дослід із навмисною помилкою

У зворотному проході видалено ділення на кількість обʼєктів у градієнті за логітами: замість $(P - Y)/N$ використовується $(P - Y)$. Функція втрат, еталон PyTorch і формула чисельної похідної залишені без змін. Запуск: `python main.py --bug`.

### Прогноз, зафіксований до запуску

1. Втрата не зміниться, оскільки помилку внесено лише у зворотний прохід, тоді як прямий прохід і формула втрати не змінювались — звірка втрати з PyTorch буде пройдена.
2. Усі ненульові градієнти зростуть рівно у $N = 105$ разів: множник $1/N$ розташований на початку ланцюга обчислень, а всі наступні операції ($A_1^{\mathsf T} \delta_2$, $\delta_2 W_2^{\mathsf T}$, множення на маску, підсумовування за рядками) є лінійними за $\delta$, тому стала проходить крізь них без змін. Нульові елементи залишаться нульовими.
3. Обидві перевірки градієнтів мають виявити помилку — як звірка з PyTorch для всіх чотирьох градієнтів, так і чисельна перевірка для всіх чотирьох параметрів, оскільки чисельна похідна обчислюється на основі незміненої втрати. Звірка самої втрати помилку не виявить.

### Аналіз відповідності прогнозу

Прогноз підтверджено за всіма трьома пунктами. Втрата збіглася з PyTorch до 2.220e-16 — на значенні втрати помилка не проявляється. Поелементне відношення зіпсованих градієнтів до коректних дорівнює 105 з точністю до $10^{-13}$ для всіх чотирьох масивів, нульові елементи серед них відсутні. Максимальні різниці в таблиці звірки відповідають $104 \cdot \max|g|$: для `W1` це $104 \cdot 0.178059 = 18.52$, аналогічно для решти параметрів. Чисельні похідні залишились незмінними порівняно з пунктом 5, оскільки втрата не змінилась, тому розбіжність із `backward()` виявлена однозначно.

Під час навчання подібна помилка не спричинила б аварійного завершення програми: градієнти залишаються скінченними й вказують у правильному напрямку. Її ефект еквівалентний збільшенню швидкості навчання у 105 разів, причому при зміні розміру пакета цей ефективний крок змінювався б відповідно. Отже, виявити таку помилку можливо лише за допомогою прямих перевірок градієнтів до початку навчання; спостереження за динамікою втрати для цього непридатне.

Після завершення досліду коректну реалізацію відновлено: без прапорця `--bug` виконується `divide_by_n=True`.

## Висновки

1. Реалізація зворотного проходу вручну збігається з результатами PyTorch autograd на рівні машинної точності, що підтверджує коректність виведених формул.
2. Чисельна перевірка демонструє узгодженість на рівні $10^{-10}$, що відповідає теоретичній оцінці похибки центральної різниці при $\varepsilon = 10^{-6}$ у `float64`. Подальше зменшення кроку недоцільне, оскільки зростатиме похибка округлення $O(u/\varepsilon)$.
3. Помилка у вигляді втраченого множника $1/N$ не впливає ні на значення втрати, ні на скінченність обчислюваних величин, тому може бути виявлена виключно прямою перевіркою градієнтів.
4. Зсув на максимум у log-softmax забезпечує результат, ідентичний вбудованій функції PyTorch, і водночас гарантує чисельну стабільність при великих значеннях логітів.
